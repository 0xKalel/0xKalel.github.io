## Connect the booking to the warehouse floor

Before SPS, staff resolved booking differences by email and did not always record item locations. SPS lets them handle the full process on a phone.

## Remove complexity the warehouse does not need

An earlier version worked offline. Every warehouse already had internet, so the extra code was hard to justify.

<div class="post-principles not-prose">
  <div class="card post-before fx">
    <p class="eyebrow">Before: offline mode</p>
    <div class="post-before-lines" aria-hidden="true"><span></span><span></span><span></span><span></span><span></span><span></span></div>
    <p>Extra code to save offline changes and sync them with StoragePal.</p>
  </div>
  <div class="card post-after fx" style="--d:70ms">
    <p class="eyebrow">After: online only</p>
    <dl>
      <div><dt>Online</dt><dd>Scanning needs a connection</dd></div>
      <div><dt>Saved</dt><dd>Sessions are saved on the server, even after a reload</dd></div>
      <div><dt>Smaller</dt><dd>Much less code to maintain</dd></div>
    </dl>
    <p class="post-after-foot"><span>Removed before daily production use began.</span></p>
  </div>
</div>

The app requires a connection to save changes. That limit keeps the system smaller and easier to maintain.

  </ol>
  <div class="post-incident-foot">

      <li>A test covers this case.</li>
    </ol>
