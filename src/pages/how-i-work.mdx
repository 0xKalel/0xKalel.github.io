## The setup, concretely

<Cards
  cols={2}
  items={[
    { icon: 'ph:book-open', title: 'Project instructions', text: 'A ~520-line instruction file per codebase: architecture, commands, conventions and the business rules that must never break, such as which invoice amounts may be summed.' },
    { icon: 'ph:shield-check', title: 'Guard hooks', text: 'Automated checks around every change: formatting and linting on save, plus a guard that blocks destructive migrations and the command class that once broke production.' },
    { icon: 'ph:stack', title: '23 reusable task instructions', text: 'Conductor instructions sequence the specialists; ops runbooks are decode tables distilled from real incidents: status codes, cooldowns, cost forensics.' },
    { icon: 'ph:detective', title: 'Read-only investigation', text: 'Dedicated read-only investigators (pipeline-detective, prod-auditor) trace problems wide without the ability to change anything.' },
    { icon: 'ph:brain', title: 'Notes that carry forward', text: '~140 recorded facts: incident write-ups, how external APIs actually behave, and each decision with its reasoning, available to every future session.' },
    { icon: 'ph:plugs-connected', title: 'The right tool access', text: 'Documentation, application context and browser control connected where they help, including a third-party server wrapped to be read-only.' },
    { icon: 'ph:browser', title: 'Checks in a real browser', text: '65 scenarios on the warehouse app, run automatically: complete workflows including failures, with network requests, console, database and logs in the report.' },
    { icon: 'ph:file-text', title: 'Decisions with their reasoning', text: 'Investigated-and-deferred records live next to the code (prompt caching, embedding curation), so a closed question stays closed until the evidence changes.' },
