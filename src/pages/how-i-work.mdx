I have shipped software for 14 years. Today Claude Code, and sometimes Codex, types most of my code. That moved my job upstream and downstream of the typing: deciding what to build, writing it down precisely enough that an agent cannot misread it, and reviewing what comes back until I would defend every line. A bug in agent-written code is my bug.

## The loop

**Specify.** What must be true and what must never happen, written before any code exists.

**Delegate.** The agent implements in small steps inside the project's rules. A 2,000-line diff is not reviewable, whoever wrote it.

**Review.** Every diff, for three things: is it correct, does it duplicate something that exists, is it more complicated than the problem needs.

**Verify.** Tests, static analysis and agent-run browser checks against the real app. Then people.

**Measure.** Small releases, checked afterwards against production data.

## What I do not delegate

- **Architecture.** On RavenClip, a database state machine over job chains and one shared failover loop instead of six were my calls. Agents implement decisions well; they do not make good ones unprompted.
- **Money and data.** Billing rules, payment retries and anything destructive are specified line by line and reviewed twice.
- **Incidents.** When 99% of orders suddenly showed as cancelled, the agent helped me read logs faster, but finding [four compounding bugs](/work/sps/) took understanding the system.

## Why this matters for a team

The value of an engineer is shifting from producing code to judging it. I bring 14 years of judgment to a workflow where code is cheap, and a setup that makes agent output consistent, reviewable and safe to ship. The deepest worked example is the [RavenClip engineering deep dive](/blog/2026/09/25/ravenclip-engineering/).
